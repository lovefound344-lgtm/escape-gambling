Phase 13.11 · WRONG_FINAL +3분 페널티 적용 안내

변경 내용
1. 최종 추리 오답 시 index.html이 WRONG_FINAL 이벤트를 Google Apps Script로 즉시 전송합니다.
2. WRONG_FINAL은 '기록' 시트의 기존 '최종보고서 오답횟수' 열에 누적됩니다.
3. 오답 1회당 +180초(+3분)가 공식 기록에 반영됩니다.
4. COMPLETE 시 서버 실제 경과시간 + (오답횟수 × 180초)로 공식 기록을 계산합니다.
5. '순위표'는 기존처럼 공식 소요초 기준으로 정렬되므로 자동으로 페널티가 반영됩니다.
6. WRONG_FINAL 전송이 일시적으로 실패해도 COMPLETE 요청의 finalAttempts 값으로 한 번 더 보완합니다.
7. 같은 attemptNumber가 중복 전송되어도 오답 횟수가 중복 증가하지 않도록 처리했습니다.

Google Apps Script 적용
- 기존 Apps Script 프로젝트의 Code.gs를 업데이트합니다.
- 중요: 제공된 Code.gs의 SPREADSHEET_ID는 이전에 전달된 템플릿 값을 그대로 유지하고 있으므로,
  실제 프로젝트에서 사용 중인 기존 SPREADSHEET_ID 값은 반드시 그대로 보존하세요.
- 배포 > 배포 관리 > 기존 웹 앱 배포 편집 > 새 버전으로 배포합니다.
- 같은 배포를 업데이트하면 /exec URL은 그대로 사용할 수 있습니다.
- 이번 변경은 기존 열을 사용하므로 setupSheets()를 다시 실행하거나 스프레드시트 열을 직접 추가할 필요가 없습니다.

GitHub Pages 적용
- index.html만 교체합니다.
- assets 폴더와 BGM 파일은 변경할 필요가 없습니다.

권장 QA
A. 새 테스트 학급으로 시작
B. 최종 추리를 1회 틀림
   → 기록 시트 '최종보고서 오답횟수' = 1 확인
C. 이후 정답 제출
   → 실제 경과시간보다 공식 기록이 정확히 3분 긴지 확인
D. 2회 오답 테스트
   → 오답횟수 = 2, 공식 기록 +6분 확인
E. 순위표가 페널티가 포함된 공식 기록 순으로 정렬되는지 확인
